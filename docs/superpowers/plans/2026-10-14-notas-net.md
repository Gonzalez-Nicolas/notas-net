# Notas Net Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App web donde se pega un link de YouTube y se obtienen, en streaming, notas en Markdown generadas por Gemini a partir del transcript.

**Architecture:** Backend ASP.NET Core Minimal API con carpetas `Application` / `Infrastructure` / `Endpoints` dentro de un único proyecto API, más un proyecto de tests. Las dependencias externas (transcript y LLM) están detrás de `ITranscriptProvider` e `ILlmProvider`. El endpoint `POST /api/notes` responde por SSE. Frontend React + Vite consume el stream con `fetch`.

**Tech Stack:** .NET 8, ASP.NET Core Minimal API, xUnit, `YoutubeExplode`, Gemini REST API (`streamGenerateContent?alt=sse`) vía `HttpClient`; React 18, TypeScript, Vite, Tailwind, `react-markdown` + `remark-gfm`, Vitest + Testing Library; Docker, GitHub Actions, Azure Container Apps + Static Web Apps.

**Spec:** `docs/superpowers/specs/2026-10-14-notas-net-design.md`

## Global Constraints

- Sin cuentas, sin base de datos, sin historial (fuera de alcance v1).
- `ILlmProvider` e `ITranscriptProvider` viven en `Application`; sus implementaciones en `Infrastructure`.
- El endpoint es `POST /api/notes` con body `{ "url": "..." }` y responde SSE con eventos `status`, `chunk`, `done`, `error`.
- URLs soportadas: `youtube.com/watch`, `youtu.be`, `shorts`.
- Códigos de error: `invalid_url`, `no_captions`, `video_unavailable`, `rate_limited`, `llm_failure`.
- El prompt vive en un archivo de recursos versionado (`Prompts/notes.system.md`), no en código.
- API key de Gemini solo por configuración/variable de entorno (`Gemini__ApiKey`); nunca en el repo.
- CORS limitado al origen configurado en `Cors__AllowedOrigin`.
- Rate limit por IP, tope de tamaño de transcript y tope diario global de requests al LLM.
- Frontend: modo claro/oscuro según sistema, responsive, mensajes de error amigables.
- Todo el texto de UI en español.

## Review Focus

- Link de YouTube con parámetros extra (`&t=30s`, `?si=...`, `&list=...`) o `www.`/`m.`: debe extraer el `videoId` igual (test en Task 1).
- Texto que no es URL, URL de otro dominio o `videoId` de longitud incorrecta: `invalid_url`, sin llamar a ningún proveedor (Task 1 y Task 4).
- Transcript vacío o de pocas palabras: `no_captions`, no una nota vacía (Task 2).
- Transcript enorme: se trunca o se hace map-reduce sin superar el tope, nunca se envía completo al LLM (Task 2).
- El cliente cancela a mitad del stream: el backend cancela la llamada a Gemini vía `CancellationToken` (Task 4) y el frontend deja de renderizar (Task 5).

  - `record NotesOptions(int MaxTranscriptChars = 400_000, int ChunkChars = 60_000, int MinWords = 30, string SystemPrompt = "")`.
  - `static class TranscriptChunker { public static IReadOnlyList<string> Split(string text, int chunkChars); }` (corta en espacios, sin partir palabras).

- [ ] **Step 1: Tests fallidos** con fakes: URL inválida → `NotesException(InvalidUrl)` y el provider nunca se invoca; transcript < `MinWords` → `NoCaptions`; flujo feliz emite `StatusEvent`, N `ChunkEvent` en el orden del LLM, y `DoneEvent` al final; transcript > `ChunkChars` → el LLM se llama una vez por parte (resúmenes parciales) y una vez final con los resúmenes unidos; transcript > `MaxTranscriptChars` se trunca a ese tope antes de dividir; cancelar el token detiene la enumeración. `TranscriptChunker`: ninguna parte supera `chunkChars` y `string.Join(" ", partes)` conserva todas las palabras.

- [ ] **Step 3:** Implementar interfaces, tipos y `TranscriptChunker`; `ExecuteAsync` en un método iterador (`yield return`). Map-reduce: parciales vía `StreamAsync` acumulados en `StringBuilder`, solo la pasada final emite `ChunkEvent`.
